## 重构方案：统一 Frame 和 FrameLocator 的接口

### 问题

* `getFrame()` 返回 `Frame`，有 `evaluate()` 方法

* `getFrameLocatorByPath()` 返回 `FrameLocator`，没有 `evaluate()` 方法

* 导致每个 action 都需要特殊处理 `FrameLocator`

### 解决方案

创建一个 `FrameWrapper` 类来封装差异：

1. **在** **`browser.ts`** **中创建** **`FrameWrapper`** **类**：

   * 封装 `Frame` 和 `FrameLocator` 的差异

   * 提供 `evaluate()`、`locator()`、`tap()` 等统一方法

   * 对于 `FrameLocator`，内部使用 `locator(':root').evaluate()` 实现

2. **修改** **`getFrame()`** **和** **`getFrameLocatorByPath()`** **方法**：

   * 都返回 `FrameWrapper` 类型

   * 保持 API 一致性

3. **恢复** **`actions.ts`** **中的代码**：

   * 撤销之前对 storage、tap 等函数的修改

   * 恢复使用 `frame.evaluate()` 的简单写法

4. **修复** **`types.ts`** **中已添加的** **`inFrame`** **属性**（保留）

5. **运行测试验证**
