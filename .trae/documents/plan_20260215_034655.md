## 创建 `getFrame` 方法的专门测试

### 测试文件结构

创建新文件：`src/__tests__/browser.getFrame.test.ts`

### 测试分类

#### 1. **同源 iframe 测试** (使用本地 fixtures)
- 单层 iframe 通过 name/ID 匹配
- 嵌套 iframe 路径解析 (`#frame1/#frame2/#frame3`)
- 索引匹配 (`0`, `1`, `2`)
- URL 部分匹配

#### 2. **跨域 iframe 测试** (使用外部 URL)
- 单层跨域 iframe 访问
- 嵌套跨域 iframe 访问 (`#frame/0` 格式)
- 验证 `childFrames()` 在跨域场景的行为
- 验证 `FrameLocator` API 的可行性

#### 3. **边界情况测试**
- 空路径返回 mainFrame
- 不存在的 frame 路径抛出错误
- 无效索引抛出错误

#### 4. **解决方案验证测试**
- 对比 `Frame.childFrames()` vs `page.frameLocator()` 的行为
- 验证 `FrameLocator` 链式调用是否支持跨域

### 测试目的

1. 确认当前 `getFrameByPath` 实现在同源场景下正常工作
2. 明确跨域场景下的限制和失败原因
3. 为后续改进（使用 FrameLocator API）提供验证基准
